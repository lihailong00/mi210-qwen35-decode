# MI210 上 DFlash7 的草稿接受率与 200 token/s

在优化后的 Q2_0 八列验证内核上，单卡 MI210、单流贪心生成，九题合计的真实 DFlash7 接受率为 **35.64%**。用前五题选择两个重排参数，再固定参数在线生成，接受率达到 **38.77%**，平均从 **3.50 提高到 3.72 token/验证轮**，decode 从 **128.0 提高到 137.5 token/s**。四条留出题每轮从 3.31 提高到 3.52 个 token。

|---|---:|---:|---:|---:|---:|---:|

| 按整段预期连续命中数择路 | 35.59% | 3.491 | 27.20 | 135.7 | 120.2 | 128.4 |
| 本次在线候选重排 | 38.77% | 3.716 | 27.02 | 144.2 | 130.1 | 137.5 |
| 已知答案，条件分数前 4 名 | 53.19% | 4.721 | 27.30 | 187.9 | 157.3 | 173.0 |
| 已知答案，条件分数前 8 名 | 60.36% | 5.213 | 26.98 | 207.9 | 177.4 | 193.2 |
| 已知答案，前五个位置从 16 个候选中选，后两位由草稿选 | 62.64% | 5.371 | 26.90 | 209.6 | 188.4 | 199.6 |
| 已知答案，七个位置均从 16 个候选中选 | 65.38% | 5.552 | 26.97 | 215.8 | 194.6 | 205.8 |

接受率用接受的草稿数除以提出的草稿数。输出 token/轮用全部输出 token 数除以服务端实际验证轮数，包含目标模型交付的 token，短请求有少量首尾边界效应。速度用总输出 token 数除以服务端总生成时间，排除 prefill。单独列出的已知答案诊断仍实际运行草稿模型和主模型验证，利用同提示的无推测贪心答案来选择真实候选。前 4 和前 8 指按此前选中 token 条件化后的候选分数排名。

以 26.9 ms/轮估算，200 token/s 需要 5.38 个输出 token/轮，约等于每轮命中 4.38 个草稿，即七个提议的约 63%。以题设 5.40 为目标，从原生选择到全 16 候选已知答案所测出的 2.06 token/轮空间中，需要拿到约 93%。这个比例针对平均输出长度。留出组即使用参考答案在 16 个候选中逐位选择，实测也只有 5.25 token/轮和 194.6 token/s；维持这份命中数时，轮时需降至 26.26 ms 才能达到 200。

## 第一处错误在哪里

在原生策略实际访问的 659 个验证起点，首个草稿命中 457 次，失败 202 次。在这 202 次中，正确 token 有 155 次已进入该位置的 16 个候选，其余 47 次缺席。全部七个位置合看，共有 550 轮出现了第一处错误，429 轮的正确 token 在该位置的候选内，121 轮缺席。某一位预测错了，它后面的正确 token 也无法被本轮接受。

## 实验方法

- 主模型为 Ternary-Bonsai-2.5-27B-Q2_0-mtp，草稿为 Bonsai 2 微调 DFlash2 Q4_K_M，K=7，沿用前次实测的八列 HIP 库。温度 0、seed 1、单槽、上下文容量 8192、F16 KV、FA 开。每个进程用 32 个 token 热身，九条提示各生成 256 个 token，关闭提示缓存。原生、在线重排和完整已知答案诊断各用三个独立进程，轮换提示顺序。预期命中数择路跑两次，受限的已知答案诊断各跑一次。
- 另外逐个已提交 token 采集一次真实草稿的候选 ID 和相邻位置的条件分数，得到每题 254 个可开始七位或截短草稿的起点。仅用标准五题挑选 80 个参数组合中需要验证轮数最少的一组，然后冻结参数。在线只使用该请求已经生成的 token、草稿先前位置所选的 token、候选次序和条件分数。对候选序号 a（从 0 开始）扣除 2 × ln(1+a) 分，已生成文本中曾跟在相同后缀后的候选再加分，匹配 2 至 5 个 token 时分别加 1 至 4 分。
- 按逐 token 采集的数据重放，原生模拟为 3.480 token/轮，实际为 3.496。完整已知答案两种方法均为 5.552。各策略在线运行时会访问不同起点和计算批形，表中的在线吞吐与接受率均取实际服务响应。
- 在同一份逐 token 轨迹上，用参考答案预知后续候选、允许故意提前截断并以动态规划最小化轮数，九题为 5.65 token/轮，留出为 5.28。此值仅约束这批固定轨迹的离线轮数。重训草稿或改变候选集后应重新评估。
- 共 144 个请求逐条核对了输出 token ID 和文本，均与无推测贪心答案相同。实验只在独立服务进程中运行。

本目录的 results.json 包含逐请求计数和时间、参数筛选摘要、按组和按题的统计及权重版本。prefix-rerank.cpp 是经这次在线复测的 Linux 单槽贪心实验模块，对应项目的 llama.cpp C++ ABI。在匹配的源码环境可用以下命令编译，再把得到的动态库置于实验服务 LD_PRELOAD 的最前面，保留原 DFlash 权重变换修正库。

```sh
g++ -O2 -std=c++17 -shared -fPIC -I"$LLAMA_CPP/include" -I"$LLAMA_CPP/common" -I"$LLAMA_CPP/ggml/include" prefix-rerank.cpp -ldl -o prefix-rerank.so
```
