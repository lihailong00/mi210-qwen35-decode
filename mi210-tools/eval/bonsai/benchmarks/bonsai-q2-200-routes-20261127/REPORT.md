# 单卡 MI210 保留 Bonsai 2.5 Q2_0 时的 200 token/s 路线

当前在线方案以 MTP=3 最快。冲击常规单请求 200 token/s，优先实验是降低 Q2_0 五至八列验证的成本，同时用 Bonsai 2.5 自身的输出改善并行草稿的连续命中长度。八列的主模型 Q2 投影单项达 20.30 ms，超过整个四列主模型验证的时间。八列验证值得先在真实权重的 401 个投影上做原型，过了速度和数值门槛再投入草稿训练。

## 在线生成

目标为同一份 Ternary-Bonsai-2.5-27B-Q2_0-mtp.gguf，单卡、单槽、温度 0、seed 1、8192 上下文、4096 batch/ubatch、F16 KV、FA 开，关闭提示缓存。标准组是英文续写、Python、中文解释、算术和 JSON；留出组是中文小词典、英文改写、Python 滚动中位数和中文 JSON。每条生成 256 token。表中为总生成 token 数除以生成时间，排除预填充；均排除热身。动态宽度取两个独立服务进程的合并值，其他筛选项各取一次。

| 在线配置 | 标准 token/s | 留出 token/s | 标准 token/轮 |
|---|---:|---:|---:|
| MTP=3，记录实际提议 | 149.7 | 134.5 | 3.01 |
| MTP=4，五列验证 | 137.5 | 129.7 | 3.33 |
| MTP=7，八列验证 | 107.7 | 97.9 | 3.88 |
| Qwen3.8 DFlash2，七个草稿 | 107.5 | 94.5 | 3.66 |
| Bonsai 2 微调 DFlash2，三个草稿 | 142.6 | 132.6 | 2.90 |
| 同一微调草稿，四个草稿 | 129.6 | 123.5 | 3.18 |
| 同一微调草稿，七个草稿 | 105.8 | 95.5 | 3.66 |
| 七候选位置，用条件概率选择预期连续命中数最大的路径 | 104.9 | 95.7 | 3.67 |
| 再根据预期命中数与轮时选择验证 3、4 或 7 个草稿 | 134.5 | 122.1 | 3.51 |

并行草稿一次提出整段。在线路径选择仅读取草稿模型给出的候选 ID 和相邻位置之间的分数。动态策略每次先出七个草稿，再选实际验证宽度。计时在 GPU 独占的独立实验服务完成。所有完成的运行均逐请求与无 MTP 的贪心参考比对了 token ID 和文本；相同提示的多次运行重复了相同参考。此前正式 MTP=3 的三次标准组综合速度为 147.51 token/s。

## 使用参考答案的诊断

| 诊断方式 | 标准 token/s | 留出 token/s | 判读 |
|---|---:|---:|---|
| 回放 MTP=3 的实际草稿 | 174.2 | 163.1 | 省掉提议计算与草稿状态追赶；两组的轮数、提议数、接受数逐请求与实时 MTP 相同 |
| 回放 MTP=7 的实际草稿 | 131.2 | 118.7 | 宽验证仍须执行，额外提议的实际命中不足以摊薄成本 |
| 在真正算出的 DFlash 候选中，已知答案，挑正确候选，固定 K=3 | 183.3 | 172.2 | 主模型和草稿模型均实际运行 |
| 同样选正确候选，固定 K=4 | 178.1 | 162.5 | 标准组每轮 4.31 token |
| 同样选正确候选，固定 K=7 | 170.1 | 142.7 | 标准每轮 5.82 token，留出每轮 5.25 token |
| 从实际候选中选正确 token，并用已知答案选 3/4/7 的验证宽度 | 189.4 | 176.7 | 两次独立进程，标准每轮 5.77 token、30.45 ms；留出 5.09 token、28.82 ms |
| DFlash 照常计算，再用正确答案替换整段七个草稿 | 228.0 | 221.3 | 每轮交付 8 个 token，测量当前软硬件在极理想命中条件下能否越过 200 |

不同验证宽度的快慢受请求组成、草稿截短和计时波动影响。参考答案参与的结果只描述所测策略，无法推出任意策略的严格上限。九条提示各输出 256 token，初始主模型 token 和生成边界会使按服务计数换算的 token/验证轮略偏离稳态值。

## 验证成本与研发门槛

在独立的阶段计时里，标准组的 MTP=3 主模型验证约 17.13 ms/轮、草稿 2.81 ms/轮。微调 DFlash2 固定七个草稿，主模型验证约 28.30 ms/轮、草稿 5.46 ms/轮。该阶段计时含实际请求里的不同长度验证轮，未计入首轮草稿之前的 prefill。

另用 GPU 追踪只看最后 20 个完整八列验证轮。257 次 Q2 矩阵投影合计的中位数为 20.30 ms；514 次输入准备为 2.66 ms，GDN 为 2.35 ms，Flash Attention 内核为 0.80 ms。此前用相同分类测得四列的 Q2 投影为 10.90 ms，257 次输入准备为 1.90 ms。当前八列代码已经复用同一份权重与解包，仍按两组四列发出矩阵指令和输入准备。阶段计时与 GPU 追踪取自不同进程。

建议第一步在保留 Q2_0 权重布局的前提下，重写八列矩阵分块，让 5–8 列共用一次输入准备。将八列投影从 20.30 ms 压到约 14–15 ms 可作为继续投入的原型门槛，这是工程目标。用真实投影输出逐位比对，再测真实服务的整轮收益。草稿侧应针对 Bonsai 2.5 的实际隐藏状态和贪心输出提高连续命中。最终验收看两组在线请求能否同时满足每轮交付至少 5 个 token、整轮至多 25 ms；其他组合也可用 token/轮除以秒/轮判定。即使按已知答案从实际候选动态择宽的命中数估计，留出组也要从 28.82 降至 25.47 ms/轮才能过线。

## DFlash 接入修正

本次首次测试 Qwen3.8 通用草稿时，九条请求中共接受零个草稿。项目的 DFlash 图借用主模型词嵌入和词表输出权重时，没有采用权重所属模型的 Hadamard 变换。独立实验库在嵌入查表后恢复原基底，并在输出投影前使用所属模型的输入变换。修正后同一草稿在标准组接受 924/2431，速度从 28.7 升至 107.5 token/s。所有 DFlash 对比均使用修正后的库，原始失败对照单列存在 results.json 中。补丁已对实验对应的工程源码通过 `git apply --check`。正式服务与主模型文件均沿用原配置。

下载的两个草稿均为 Q4_K_M，按固定仓库修订和 SHA-256 校验，存放在远端独立实验目录。一个面向基础模型 Qwen3.8-27B，另一个针对 Bonsai 2 微调；两者都没有声明使用 Bonsai 2.5 训练。[基础草稿模型卡](https://huggingface.co/z-lab/Qwen3.8-27B-DFlash2-GGUF) · [Bonsai 2 微调草稿模型卡](https://huggingface.co/Schiltmans/Ternary-Bonsai-2-27B-DFlash2-ft5-GGUF) · [Bonsai 2.5 目标模型卡](https://huggingface.co/prism-ml/Ternary-Bonsai-2.5-27B-GGUF)
