# MI210 上 Bonsai K=3 验证耗时与带宽

单卡 MI210，Ternary-Bonsai-2.5-27B-Q2_0-mtp，使用已验证的 Q2_0 多列内核。开启 MTP 后，五个短提示各生成 256 token。采用与此前相同的贪心、单请求和 F16 KV 设置。

| K=3 的平均每轮耗时 | ms |
|---|---:|
| 主模型验证（到现有 GPU 同步点） | 30.21 |
| 草稿生成 | 2.83 |
| 草稿状态跟进 | 0.20 |
| 其余时间，包括采样和调度 | 0.51 |
| 合计 | 33.75 |

两次 K=3 各实际验证 425 轮、生成 1,280 token，合计平均每轮交付 3.012 个 token。分阶段测量为 89.23 token/s，上次无计时探针为 89.44。作为对照，同一组提示 K=2 测得 95.24，关闭 MTP 为 81.29 token/s。四次运行的 token 序列和文本都与原参考一致。

对主模型的完整四列验证另做了两次独立采样。rocprofv3 在标记的主模型区间中，最后 20 个完整四列步骤每步均调用 401 次 Q2_0 内核，中位累计时长 23.87 ms。独立的 FETCH_SIZE 硬件计数器采集在 15 个完整步骤中测得，中位读取量 7.217 GB，中位内核累计时长 24.92 ms，对应约 290 GB/s。与模型中相应 401 个矩阵的 7.200 GB 权重大小接近。追踪和计数器运行会扰动调度，端到端速度使用普通计时运行，不使用 profiler 的总时长。

本机纯读微基准为 1,361 GB/s（4 GB）至 1,446 GB/s（48 MB）。仅搬运这 7.217 GB 的参考耗时为 5.0–5.3 ms。实测 Q2_0 验证内核的平均读带宽约为纯读的 20–21%。这一比较没有计入解包、点积、归约、注意力等计算成本，不能用来承诺整模提速倍数或判断每个内部单元的饱和度。

保持草稿接受率和其他每轮用时不变，主模型验证若从 30.21 ms 降到 22 ms，折算约 118 token/s；降到 20 ms，对应约 128 token/s。要到 245 token/s，主模型验证预算只有约 8.75 ms。优先比较当前逐列 dp4a 实现与四列共享解包、使用 MI210 INT8 MFMA 矩阵指令的方案，并逐列检查与单 token 路径的输出一致性。以上速度均是按时间预算计算的情景值。

计时探针仅在诊断进程中包围服务已有调用，没有增加 GPU 同步。每个请求从第一轮草稿开始统计，剔除预热和 prefill。主模型时间到原有同步点为止，草稿状态跟进项是 CPU 调用耗时。子阶段采用墙钟归属，异步工作可能在后续等待点体现。GPU kernel 追踪和硬件流量采集分开进行。
