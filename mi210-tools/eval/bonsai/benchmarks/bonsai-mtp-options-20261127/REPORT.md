# MI210 上 Bonsai 27B 的下一步优化选择

当前最值得工程化的候选是保留 MTP=3，把草稿词表投影限制为前 131,072 行。主模型仍使用全部 248,320 个词表项，逐个验证草稿。这个原型使用正式构建的相同四行交错 Q2_0 权重，保留符号乘法与 1024 点 Hadamard 变换，复用完整权重的重排缓存，把未计算的草稿 logits 设为负无穷。实验在独立服务进程和独立运行库中完成。

## 真实请求

每对测试交错运行同一实验构建的完整词表和短词表模式。吞吐取所有请求返回的 token 数除以服务端生成总时间。单卡 MI210 gfx90a，单槽请求，贪心、固定种子、提示缓存关闭，8192 上下文，batch 和 ubatch 均为 4096，F16 KV，FA 开启。表中均为实际生成吞吐。

| 提示与生成长度 | 独立进程对数 | 完整词表 token/s | 草稿短词表 token/s | 变化 | 短词表单对胜数 |
|---|---:|---:|---:|---:|---:|
| 标准五条提示，各生成 256 token | 3 | 148.07 | 152.17 | +2.77% | 3 |
| 两条标准提示，各生成 1,024 token | 2 | 145.41 | 148.60 | +2.19% | 2 |
| 另外四条中英文提示，各生成 256 token | 3 | 140.30 | 141.77 | +1.04% | 2 |

标准短请求的草稿接受数从 848/1,272 变成 844/1,284。在独立阶段计时中，草稿生成从每轮 2.80 ms 降到 2.32 ms，同样交付 1,280 个 token 的验证轮数从 425 增至 429。三组交错对照中，候选的全部 31 个请求均与相同提示的无 MTP 贪心参考逐 token、逐文本一致。单轮筛选用的样本未计入交错对照表。新提示的增益小于标准短请求，结果依赖负载。

工程化时要在当前模型的 MTP 输出头上明确传递“只计算部分草稿词表”的信息。原型用图节点名字识别仅在草稿图出现的投影，固定 MI210 和本模型的形状。正式版本需要显式表示该操作，并覆盖适配器、回退路径和更多语言。正式运行库继续使用完整词表。

## 现有词表开关

在项目原有分支，LLAMA_MTP_DRAFT_VOCAB 先对权重建立前缀视图，再按权重对象查找 Hadamard 变换。原权重有变换记录，视图没有；重排缓存也会排除权重视图。用原有开关测试 32,768、65,536、131,072、196,608 四个长度，每档五条短提示都是 0/3,795 个草稿被接受。主模型验证后最终输出仍正确。建议保留原权重对象及变换关系，让草稿投影内核控制行范围。

修正路径的单轮筛选中，65,536 行得 129.03 token/s，其中中文提示的草稿接受数从全词表的 158 降至 82；131,072 行该提示接受 157 个。短词表只改变提议分布，词表覆盖不足会抵消更少的显存读取。

## 加深 MTP 的成本

现有正式构建直接使用 K=4 得 86.00 token/s，五条短提示仅三条与无 MTP 参考完全一致。另建 5–8 列验证原型，将列分为两个四列组，两组共用同一份权重读取与解包。36 种宽度、列数和投影数的组合各测三种输入，247,104 个 FP32 输出逐位等于独立单列计算。每个草稿深度的五条标准提示都与无 MTP 参考完全一致。

| 最大草稿数 | K=3 | K=4 | K=5 | K=6 | K=7 |
|---|---:|---:|---:|---:|---:|
| 独立宽验证构建，单轮 token/s | 154.20 | 124.35 | 122.74 | 119.07 | 109.24 |

单独对服务阶段计时，K=3/4/5 分别平均交付 3.012、3.333、3.516 token/轮，耗时分别为 20.79、26.49、28.94 ms/轮。K=4 若要达到 150 token/s，需要降至 22.22 ms/轮。

跟踪完整验证轮时，四列到五列的 Q2 矩阵累加耗时从 10.90 增至 15.24 ms。当前宽验证原型把第五列放进第二组，仍执行第二组四列的矩阵指令。输入准备也从 257 次变成 514 次启动，耗时从 1.90 增至 3.20 ms。若继续做宽验证，应优先测第五列的专用计算，并让两组共享一次输入准备启动。GPU 追踪与服务分阶段测量来自不同运行，各自的耗时不能直接相加。

## 其他筛选与校验

- 草稿置信度阈值从 0 调到 0.35 和 0.65，短请求的单轮吞吐分别为 143.83 和 138.23 token/s。同组基线为 150.01 token/s。阈值上升后接受比例上升，但可接受的草稿总数下降。
- n-gram 与 MTP 并用时，简单匹配与基线的接受数相同，三元前缀映射为 141.90 token/s。默认采样链启用主模型后端采样时，ROCm 日志报 top-p 所需的 ARGSORT 不受支持；将采样链精简为 temperature 后也未观察到明显优势。这些都是单轮筛选。
- 关闭多列预先生成 Q8 缓存的开关，三对交错对照从 150.15 变为 150.23 token/s。
- 草稿头另用四组输入直接比对，524,288 个保留的 FP32 logits 与完整头逐位相同，468,992 个被排除的 logits 全部为负无穷。
- 实验构建的一次链接误写了一个生成的编译目标文件。已用原编译命令重建，并独立重新链接验证，所得 HIP 运行库与正式后端的 SHA-256 相同，均为 b98583965bed679cb35986669341228c35866d71d8addafc6f7103ac2e058d68。服务器没有启用实验参数。

results.json 保存各次独立进程和每个请求的计时、接受数、显存、输出比对、阶段及 GPU 分类统计。两个 probe.patch 分别保存草稿短词表及宽验证原型，均按上一版输入融合源码独立做过 git apply --check。
