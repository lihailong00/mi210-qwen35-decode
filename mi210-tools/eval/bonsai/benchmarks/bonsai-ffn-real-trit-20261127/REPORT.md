# Bonsai 27B 真实 FFN 权重的无损三值打包

在单卡 MI210 的 llama.cpp MTP=3 验证中，最快的三值实现每轮实际少读取 **0.802 GB**，FFN 的 GPU 时间却从 **6.86 ms 增至 7.98 ms**。同一实验构建上，普通请求的综合生成速度从 **150.89 降至 136.39 token/s**。实验在独立运行库中完成，正式后端继续使用原 Q2_0 布局。

## 每轮耗时

| 口径 | Q2_0 | 无损三值，共享内存查表 | 增加 |
|---|---:|---:|---:|
| 64 层 FFN 独立重放 | 6.756 ms | 7.653 ms | 0.897 ms |
| 真实服务四列验证，gate/up 投影 | 4.457 ms | 5.201 ms | 0.743 ms |
| 真实服务四列验证，down 投影 | 2.403 ms | 2.785 ms | 0.381 ms |
| 真实服务四列验证，FFN 投影合计 | 6.858 ms | 7.984 ms | 1.127 ms |
| 完整生成时间除以验证轮数，未插桩 | 19.960 ms | 22.083 ms | 2.123 ms |

独立重放直接从 `Ternary-Bonsai-2.5-27B-Q2_0-mtp.gguf` 读取 64 层 gate、up、down 的全部 192 个原始权重张量。基线走现有 Q2_0 四行交错重排，实验组将每 64 个三值权重编码为 13 字节，保留原始的 2 字节缩放。打包在计时前完成。权重载荷从 4,812,963,840 变为 4,010,803,200 字节。

独立重放使用固定种子的四列 Q8 激活，各层有独立输入，gate/up 共享输入。每个 GPU 图按层顺序执行 64 次 gate/up 和 64 次 down。两次独立进程，每次 16 组轮换顺序的测量，每个样本先预热再计时四次重放。表中第一行是 32 个样本的中位数；逐组求相对基线的时间差再取中位数，增加 0.892 ms。三种解码内核的整轮中位数分别为全局查表 13.537 ms、共享内存查表 7.653 ms、整数运算解码 10.548 ms。

服务测量直接使用模型推理生成的激活。将 20 个完整四列验证轮的内核按 GPU 开始时间排序，逐一核对 257 个投影启动的输出大小，并确认每轮 64 个 gate/up 和 64 个 down 都进入预期内核。表中各行分别取中位数。另一次独立计数器采样中，FFN 的 `FETCH_SIZE` 从 **4.821 降至 4.019 GB/轮**。每个线程块使用的 LDS 从 4,608 增至 5,632 字节，基线 gate/up、down 各用 100、96 个 VGPR，候选各用 104 个。两组的 scratch 都是 0。数据表明字节减少的收益被新的解码路径抵消，各条指令对回退的贡献尚未单独测定。

## 服务吞吐与输出核对

测试单卡、单请求、MTP=3、贪心、seed 1、8192 上下文、4096 batch/ubatch、FA 开启、F16 KV、关闭提示缓存。每次独立启动后先预热，再跑英文续写、Python、中文解释、算术与 JSON，各生成 256 token。每个配置启动三次，采用开关交错的顺序，吞吐按总输出 token 除以总生成时间计算，排除 prefill。

| 配置 | 三次独立运行，token/s | 综合 token/s | 每次验证轮数 | 每次草稿接受数/提议数 |
|---|---|---:|---:|---:|
| Q2_0 | 152.95、147.54、152.30 | 150.89 | 425 | 848/1272 |
| 无损三值，共享内存查表 | 136.81、136.52、135.84 | 136.39 | 425 | 848/1272 |

两种三值存储方式均逐块还原了全部 **17,112,760,320 个权重**和 **267,386,880 个 FP16 缩放值**。两套独立输入各产生 10,223,616 个 FP32 输出，三种解码实现都与基线逐位一致。六次服务运行的 30 个请求共返回 7,680 个 token，逐 token、逐文本等于关闭 MTP 的同模型贪心参考。正式 HIP 后端和 llama-server 的 SHA-256 已复核。

## 复现独立重放

使用支持本模型 Q2_0 类型的 llama.cpp 分支提供的 Python `gguf` 模块。以下命令在有 HIP 编译器的 MI210 环境运行，`MODEL` 指向本地原始 GGUF。

```sh
python3 ffn-manifest.py "$MODEL" weights.tsv
hipcc -O3 -std=c++17 --offload-arch=gfx90a ffn-trit-bench.hip -o ffn-trit-bench
./ffn-trit-bench weights.tsv "$MODEL" 0
./ffn-trit-bench weights.tsv "$MODEL" 2
```

`results.json` 保留逐次重放、逐请求服务时间、两类 GPU 测量和校验记录。`ffn-trit-server.patch` 对应独立服务实验，已在此次测试使用的源码上通过 `git apply --check`。私有构建以 `BONSAI_FFN_TRIT=1` 打开四列 FFN 路径，格式仅针对已经全量确认只含三种码值的该 GGUF。该服务进程还为其他列数保留 Q2_0 缓存，因此每轮少读的字节不能作为整卡常驻显存节省量。
