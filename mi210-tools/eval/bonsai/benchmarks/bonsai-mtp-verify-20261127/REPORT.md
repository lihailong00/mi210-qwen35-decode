# Bonsai 在 MI210 上的 MTP 多 token 验证

短提示、单请求、同一优化版二进制。新增 Q2_0 HIP 内核一次读取权重，计算 2、3 或 4 列输入。每列沿用原单 token 内核的浮点累加和归约顺序。仅普通稠密矩阵走新路径，未支持的融合和形状沿用原来的实现。

| 设置 | 综合 decode（token/s） | 三轮各自速度 | 草稿接受率 | 贪心输出 |
|---|---:|---|---:|---|
| 关闭 MTP | 81.83 | 82.07, 81.64, 81.78 | — | 15/15 相同 |
| K=2，通用验证 | 83.56 | 84.18, 84.15, 82.39 | 74.7% | 15/15 相同 |
| K=2，优化验证 | 96.96 | 95.85, 97.66, 97.38 | 74.7% | 15/15 相同 |
| K=3，优化验证 | 89.44 | 88.77, 90.14, 89.43 | 66.7% | 15/15 相同 |

K=2 的同开关对照为 83.56 → 96.96 token/s（+16.0%），相对本轮关闭 MTP 的 81.83 token/s 提高 18.5%。每轮的草稿计数均为 762/1020。五个请求合计 1280 个输出 token，按服务日志四舍五入的每轮交付数反推，约有 512 次验证，即约 2.5 token/轮。用总 decode 时间摊销，整轮从约 29.9 ms 降到 25.8 ms。该口径包含草稿生成、主模型验证和调度。

每种配置 3 次独立启动，各生成 5×256 token。提示、预热、greedy、seed=1、禁用提示缓存、8192 context、FA、F16 KV 和 4096 batch/ubatch 与前次筛选相同。所有 GPU 运行经共享锁、温度与超时监控。指标是总生成 token / 总 decode 秒数。每次请求的原始时间和草稿计数见 results.json。

验证开关为 GGML_MMVQ_Q2_0_VERIFY_BATCH（默认启用，设 0 关闭，仅影响新多列内核）。K=2 的服务器参数为 --spec-type draft-mtp --spec-draft-n-max 2。

34 项 Q2_0 算子测试在开启、关闭时分别通过。6 个 K × 3 种列数（含需 padding 的 4352 和上界 32768），共 13824 个 float32 值，逐列与逐 token 调用逐位相同。Qwen IQ3_S 的 128 token 原始 logits 哈希与改动前一致，tg128 为 80.58 token/s。K=5 曾出现输出差异，此轮未重新验收。
