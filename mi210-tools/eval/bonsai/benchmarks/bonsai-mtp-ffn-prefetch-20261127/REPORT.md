# MI210 上 Bonsai 27B 的 FFN gate/up 优化实验

单卡 MI210，MTP=3，llama.cpp HIP。候选内核在隔离测试和完整验证图的 GPU 内核追踪中都更快，默认服务器配置下的生成吞吐却下降。服务器已恢复上一版输入融合与分组投影后端。

## 真实请求

| 配置和工作负载 | 独立进程对数 | 对照 token/s | 候选 token/s | 变化 | 候选较快的对数 |
|---|---:|---:|---:|---:|---:|
| 单 wave，五条短提示各生成 256 token | 8 | 150.88 | 148.71 | -1.43% | 2 |
| 单 wave，两条提示各生成 1,024 token | 4 | 146.38 | 142.88 | -2.39% | 0 |
| 单 wave，4,096-token 输入生成 256 token | 1 | 155.46 | 152.76 | -1.73% | 0 |
| 仅固定形状，五条提示各生成 256 token | 6 | 149.75 | 148.64 | -0.74% | 3 |
| 单 wave，整张 HIP 图一次重放，五条提示各生成 256 token | 3 | 149.85 | 150.50 | +0.43% | 2 |

每行独立做开关交错对照，两态使用相同构建、图设置、提示和采样参数。每个进程先预热 32 token；统计总交付 token 数除以服务端生成总秒数。单槽，8192 上下文，batch/ubatch 4096，F16 KV，FA 开启，seed 1，贪心，提示缓存关闭。常规 HIP 图每 512 个图节点分段。最后一行是独立诊断，两态均覆盖该设置。

常规 K=3 短提示每次共交付 1,280 token，草稿接受数均为 848/1272。两态合计核对了 20,480 个短请求输出 token。长生成两态另核对了 16,384 个 token，都与各自的无 MTP 参考逐一一致。显存按整卡每 0.5 秒采样，短提示峰值为 18.40 → 18.40 GiB。

## 内核与整轮验证

候选处理两张输入维度为 5,120、输出维度为 17,408 的 Q2_0 权重，共享四列 Q8 激活。第一轮筛选比较了每块分工、提前载入的 K 切片数和并行计算的行数。第二轮在单个 64 线程 wave 内完成 FP32 树形归约。实测最佳配置在当前切片先加载两个行组的权重和缩放，交错发出它们的整数矩阵指令。一次预取更多切片增加了耗时。另一候选只固定矩阵形状，复用原 128 线程内核。

| 单 wave 版本 | 对照 ms | 候选 ms |
|---|---:|---:|
| 仅重放 64 层 gate/up，中位数 | 4.60 | 3.92 |
| 按顺序重放 401 个投影及输入准备，15 轮中位数 | 11.51 | 10.92 |
| 真实服务器，20 个完整四列验证轮中 gate/up 内核时间的中位数 | 4.54 | 4.05 |
| 独立服务阶段计时，主模型验证平均每轮 | 16.47 | 17.30 |
| 同一次阶段计时，草稿生成平均每轮 | 2.81 | 2.84 |

两组阶段计时各有两个进程，每进程 425 个验证轮。内核追踪、服务阶段计时和未插桩吞吐各自独立。各口径的时间差不能直接相加。

硬件计数器采样中，gate/up 每轮读取约 3.21 GB，两态都没有寄存器溢出到 scratch。新内核将每块 LDS 从 4,608 字节降至 0，每线程 VGPR 从 100 增至 120。只追踪 HIP API 的 20 个稳定轮次中，两态各发起 6 次图重放，均未发生图更新，主机提交合计都约 0.02 ms。现有测量没有定位到一个足以解释服务回退的单一原因。

对 down 也比较了 15 种配置。64 层隔离重放中，通用版为 2.34 ms，最快候选为 2.49 ms，因此服务实验沿用原 down 内核。

## 正确性与恢复

- 原有的 34 个 Q2_0 算子测试通过。增加真实 gate/up 维度的图测试后，通用与单 wave 版本的 853,656 个 FP32 输出逐字节一致，包含非二元缩放输入、同图多次执行和全零输入。
- Bonsai 512 token 及 Qwen IQ3_S 128 token 的原始 logits 与保存的参考逐字节一致。
- 恢复了实验前的内核与测试源码，并重新构建。正式 HIP 运行库与上一版的 SHA-256 均为 b98583965bed679cb35986669341228c35866d71d8addafc6f7103ac2e058d68。默认设置重跑五条提示，实测 150.36 token/s，1,280 个输出 token 全部匹配。该速度来自一次恢复检查。
- q2-ffn-wave.patch 与 q2-ffn-fixed.patch 是两个独立实验补丁，可分别应用于上一版融合输入的基线。两次应用检查均通过。设置 GGML_MMVQ_Q2_0_FFN_GATE_UP=0 可在对应实验构建中切回通用内核。逐请求数据、独立样本、原始输出校验值与 GPU 统计见 results.json。
