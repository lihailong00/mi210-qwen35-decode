# MI210 上 Bonsai 27B 的下一步优化

单请求贪心 decode 保留 MTP=3。下一项优先实验是减少主模型四列验证时读取的 FFN 权重字节。先用原始模型的 64 层 gate、up、down 权重重放，比较当前布局与无损三进制打包的完整投影耗时。压缩方案还没有 GPU 推理速度数据。

## FFN 的时间和字节

从已有的真实服务 GPU 追踪中取最后 20 个完整四列验证轮。将每轮 257 个 Q2 投影启动按 GPU 开始时间排序，与已记录的模型执行顺序匹配，逐项核对输出行数和网格大小。下表列出各类投影每轮耗时的中位数。字节数按实际权重形状和 Q2_0 布局计算。

| 投影 | 启动次数/轮 | 时间 ms/轮 | 权重 GB |
|---|---:|---:|---:|
| FFN gate 和 up | 64 | 4.50 | 3.209 |
| FFN down | 64 | 2.40 | 1.604 |
| 线性注意力 QKV 和 gate | 48 | 1.72 | 1.132 |
| 状态空间输出 | 48 | 1.04 | 0.425 |
| 全注意力 Q/K/V | 16 | 0.53 | 0.330 |
| 全注意力输出 | 16 | 0.30 | 0.142 |
| 最终词表投影 | 1 | 0.42 | 0.358 |

FFN 两类合计约 6.9 ms，约占全部 Q2 投影 10.90 ms 的 63%。逐字节检查模型的 401 个主模型 Q2 投影，第四种二位编码出现 0 次。192 个 FFN 权重张量含 17,112,760,320 个三值权重，编码 0、1、2、3 的出现次数分别为 5,754,269,850、5,605,799,051、5,752,691,419、0。

五个三值权重共有 243 种组合，可存入一个字节。每 64 个权重用 13 字节编码，加原有 2 字节缩放，共 15 字节，当前为 18 字节。FFN 的紧凑权重载荷可从 4,812,963,840 字节降至 4,010,803,200 字节，每轮少读约 0.802 GB。实际显存流量还受对齐、访存合并与缓存影响。按 FFN 内核的 6.9 ms 全部随字节数等比缩放举例，节省约 1.15 ms；这个算例未计入解包成本。

建议在加载时一次性重排，运行时直接向四列矩阵指令提供有符号权重。保留原缩放和 FP32 归约顺序，同时核对输出、实际读取字节与投影总时间。作为进入整机测试的工程门槛，可先要求 FFN 重放节省至少 0.7 ms，再以相同提示的交错服务测试和逐 token 对照决定是否采用。

## 已筛选的替代路径

**五列验证。** 在独立 llama.cpp 构建中为 K=4 实现一次启动准备五列输入，前四列使用 MFMA，第五列用整数字节点积并复用同一份权重。独立数值测试覆盖 5–8 列、三种宽度、三种投影数，247,104 个 FP32 结果与此前逐列校验的参考逐位相同。只改变了五列路径。两种 K 各用两个独立进程，运行顺序为 3、4、4、3，每次五条固定提示各生成 256 token。20 个请求均与关闭 MTP 的参考逐 token、逐文本一致。

| 配置 | 两次各自的 token/s | 综合 token/s | token/验证轮 | ms/验证轮 |
|---|---|---:|---:|---:|
| K=3，四列验证 | 155.60、145.68 | 150.48 | 3.012 | 20.01 |
| K=4，专用五列验证 | 137.93、138.05 | 137.99 | 3.333 | 24.16 |

综合吞吐取总生成 token 数除以总生成耗时，排除 prefill。轮时按同一批请求的生成总时间和服务验证计数计算。按本次接受情况，K=4 要追平 K=3 约需降到 22.15 ms/轮。

**三个草稿位置的分配。** 另在完整词表 K=3 服务中记录每个草稿位置的前三候选与主模型的首个分歧 token。五条标准提示和四条留出提示各生成 256 token，2,304 个输出 token 均与各自无 MTP 参考一致。每个请求剔除最后一个验证轮，避免生成长度限制截短草稿。按接受 0、1、2、3 个草稿分组，标准组为 78、68、53、221 轮，留出组为 82、73、36、167 轮。

考虑用第三个位置验证第一或第二步的第二候选，并保留前两步的首选链。在原轮次固定且能事先知道何时分支的情况下，这一改动最多能在标准组多交付 61/420 = 0.145 token/轮，留出组为 55/358 = 0.154。按标准组在 0.05 网格上选择两步的置信差阈值后，固定规则在标准组净增 12 个 token，留出组净减 2 个。这里回放的是已有轮次，没有运行树形验证，也没有测得分支后的端到端速度。

**四列投影内核。** 用 401 个真实形状和 257 个投影分组重放合成权重，轮换顺序取九次中位数。省去权重解包、仍执行八次矩阵指令的诊断从 10.58 变为 10.51 ms；进一步把八次矩阵指令替换为一次、保留输入读取及归约的诊断为 9.09 ms。这两种诊断改变计算结果，只用于定位。数值完全相同的双累加链和四累加链分别为 10.67、13.05 ms。另一组将相邻缩放与权重按 8、16、32 个 K 块紧邻存放，载荷大小相同，分别为 10.68、10.69、10.87 ms，同组基线 10.58 ms。后三种布局均核对了 16,590,848 个 FP32 输出。

机器上的正式 HIP 库和 llama-server 可执行文件均与此前记录的 SHA-256 一致。分项计时来自 GPU 追踪，服务速度来自独立的未插桩进程。相应的逐次计时、输出比对和权重计数保存在同目录的 results.json。
