# Bonsai Q2_0：MTP 实测

2026-11-27，使用上一轮 Q2_0 优化后的同一 llama.cpp 构建，单卡 MI210、ROCm 7.2.1。此次只测试 MTP 参数，没有修改推理内核。

结论：K=2 在这组提示上的综合 decode 为 82.04 token/s，相比关闭时 80.02 token/s 提高 2.52%。收益很小且依赖内容，不能套用此前 Qwen 的 MTP 提升幅度。K=5 未通过输出一致性检查。

## 配置比较

速度按总生成 token 数 / 总 decode 时间计算，排除 prompt 处理和服务启动；不是 SSE chunk 频率。服务器自身的 predicted_per_second 会扣除首 token，因此比这里低约 0.4%。

| 设置 | token/s | 相对关闭 | 草稿接受率 | 独立进程轮数 | 相同贪心输出 |
| --- | ---: | ---: | ---: | ---: | --- |
| 关闭 | 80.02 | +0.00% | — | 3 | 全部一致 |
| K=1 | 79.78 | -0.30% | 85.2% | 3 | 全部一致 |
| K=2 | 82.04 | +2.52% | 74.7% | 3 | 全部一致 |
| K=3 | 70.10 | -12.40% | 66.7% | 3 | 全部一致 |
| K=5 | 74.28 | -7.17% | 55.0% | 1 | 3/5 一致，排除 |

K=0/1/2/3 每种 3 个独立服务进程，每轮 5 个提示、每提示生成 256 token，即每配置 3840 token。K=5 只做一轮筛选，未通过一致性检查后未参与候选复测。实际进程顺序及命令保存在 jobs 和运行日志中；通过同一 GPU 锁交替执行，运行前降温至 60°C 以下。

## K=2 分项

| 提示类型 | MTP 关闭 | K=2 | 变化 |
| --- | ---: | ---: | ---: |
| 英文续写 | 80.03 | 69.24 | -13.5% |
| Python 代码 | 80.07 | 91.19 | +13.9% |
| 中文解释 | 80.00 | 71.54 | -10.6% |
| 算术 | 79.99 | 90.89 | +13.6% |
| JSON | 80.03 | 94.75 | +18.4% |

原始提示保存在 prompts.json：英文续写、合并有序列表的 Python 代码、中文带宽解释、算术、JSON。均为 /completion 原始提示，不是 chat 模板；temperature=0、seed=1、ignore_eos=true、禁用 prompt cache。固定生成长度便于对比，不把强制生成结束当作自然回答结束。

所有配置都是 np=1、context=8192、batch=4096、ubatch=4096、8 CPU threads、F16 KV、FA on、全层 GPU offload。每个服务启动后先用 Hello 生成 32 token 预热。没有假接受率或合成验证开关。

## 正确性和资源

- K=1/2/3 的每条输出，在三轮中均与关闭 MTP 时的文本及 token 序列逐字节一致；结论只覆盖本次提示集。
- K=5 的英文、代码输出分别从生成 token 的零基索引 34、90 开始分叉，其余三条一致。未隔离定位根因，因此不将这个设置作为可接受配置。
- MTP 关闭峰值显存 16.61 GiB；K=2 为 18.25 GiB。这是 context=8192 服务模式，不能直接与空上下文 llama-bench 显存比较。
- 本次没有新增或修改推理后端代码。libggml-hip.so SHA-256 保持 b4665f08566308dbed1164c79ae9a980b57facfacdcd4316ec72c7adf89c2b6d。
- 所有测试服务已退出，未建立常驻服务。

## 为什么没有明显提速

代码检查确认，上轮新增的 Q2_0 内核在 mmvq.cu 中只在单列输入时调用，mmvq-q2-0.cu 也要求单列输出。项目现有的多列快速路径覆盖 IQ3/IQ4/Q4_K 等类型，不包含 Q2_0。因此 MTP 一次验证多个 token 时，主干 Q2_0 矩阵不能使用上轮的单 token 快路径。

这解释了一个确定的覆盖缺口，但本次没有做逐阶段 GPU 时间分解，不能据此断言全部额外开销都来自这一项。草稿接受率同样影响收益。下一步若继续优化，应优先补齐 Q2_0 的多列验证路径，并保持每列与单 token 路径一致。

## 复现

在 mi210-opt 容器内，向现有 llama-server 启动命令添加：

```bash
--spec-type draft-mtp --spec-draft-n-max 2
```

完整示例：

```bash
${LLAMA_CPP}/build/bin/llama-server \
  -m $MODEL \
  -ngl 99 -fa on -t 8 -b 4096 -ub 4096 -ctk f16 -ctv f16 -c 8192 -np 1 \
  --host 127.0.0.1 --port 18088 --no-webui \
  --spec-type draft-mtp --spec-draft-n-max 2
```
