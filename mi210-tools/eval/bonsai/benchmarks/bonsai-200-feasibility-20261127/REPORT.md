# 单卡 MI210 上的 200 token/s 可行性测试

比较同一 Bonsai 27B Q2_0 在五条常规提示和四条高可预测性诊断提示上的单请求生成速度。每种配置使用三个独立服务进程，每进程预热后跑完同一组九条提示，三次轮换提示顺序。速度为返回 token 总数除以服务报告的生成总秒数，表内每格汇总三次。

| 配置 | 常规五条混合 | SQL 数据续写 | CSV 数据续写 | 清单复制 | 四色循环对照 |
|---|---:|---:|---:|---:|
| 正式版 MTP=3 | 147.51 | 165.59 | 193.33 | 146.22 | 196.45 |
| 草稿短词表原型，MTP=3 | 150.83 | 170.86 | 198.63 | 150.75 | 202.75 |
| 历史匹配与 MTP=3 组合（ngram-map-k） | 144.19 | 159.60 | 175.33 | 143.74 | 206.23 |
| 仅历史匹配（ngram-simple，最长 3 个草稿） | 76.46 | 90.75 | 108.21 | 100.37 | 170.68 |

单位为 token/s。常规组包含英文续写、代码、中文解释、算术与 JSON，每条生成 256 token。四种诊断提示各生成 512 token。SQL 和 CSV 都是按给定格式继续编写测试数据，清单复制要求逐字复制输入，四色循环是特意设置的极易预测对照。

## 常规负载的预算

正式版每轮平均交付 3.012 个 token，每轮 20.42 ms，综合 147.51 token/s。保持这组接受情况，200 token/s 要求每轮 15.06 ms，需节省 5.36 ms（26.2%）。若轮时不变，需要平均交付 4.08 个 token/轮；K=3 理想稳态最多交付四个。另一个等价的目标组合是 3.4 个 token/轮、17.0 ms/轮，两项均需实际改善。

短词表原型本轮混合速度为 150.83 token/s，每轮交付 2.984 个 token，轮时 19.78 ms。保持接受情况，要达到 200 需降到 14.92 ms/轮，节省 4.86 ms（24.6%）。保持当前轮时则要平均每轮交付约 3.96 个 token。

上一轮独立阶段计时测得完整词表主模型验证 17.28 ms/轮、草稿 2.80 ms/轮；短词表原型的草稿为 2.32 ms/轮。该组分段测量说明主模型验证本身已超过常规负载达到 200 时的整轮预算。

## 运行条件与核对

- 单卡 MI210 gfx90a、单槽，8192 上下文、4096 batch/ubatch、FA 开启、F16 KV，贪心、seed 1，关闭提示缓存，固定长度生成，忽略 EOS。所有请求正常执行草稿与主模型验证，未使用合成接受率。
- 每个配置有 27 个完整请求。以正式版无 MTP 的输出为参考，逐个核对 token ID 和文本。
- 正式版 MTP=3匹配 27/27 个请求。
- 草稿短词表原型，MTP=3匹配 27/27 个请求。
- 历史匹配与 MTP=3 组合（ngram-map-k）匹配 27/27 个请求。
- 仅历史匹配（ngram-simple，最长 3 个草稿）匹配 27/27 个请求。
- 指标排除 prefill 和 HTTP 往返，results.json 同时保留了各请求的提示处理时间、HTTP 墙钟、接受数和验证计数。复制和数据续写的核对标准是同一模型的贪心结果，不评价语法或作业质量。
- 短词表原型仅在独立目录中启动，对草稿头取前 131,072 行，主模型保持完整词表。已复核正式后端和服务可执行文件的 SHA-256。
