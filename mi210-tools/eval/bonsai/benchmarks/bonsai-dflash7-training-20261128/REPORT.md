# 用 Bonsai 2.5 的生成轨迹训练 DFlash7 候选打分

四道留出题、1,000 个完全相同的验证起点上，前五个草稿 token 连续命中率由原生的 31.3%、手工重排的 38.4%，提高到训练后的 **40.0%**。相对手工重排多命中 16 个起点。把打分器放回实际生成循环后，九题合计 **135.2 token/s**，同场手工重排为 136.5 token/s，低于 200 token/s 的目标。

## 前五位连续命中

| 策略 | 留出题相同起点，五位全中 | 留出题实际验证轮，五位全中 | 九题输出 token/轮 | 留出四题 token/s | 九题 token/s |
|---|---:|---:|---:|---:|---:|
| 原生 DFlash7 | 313/1000（31.3%） | 59/306（19.28%） | 3.496 | 121.6 | 129.4 |
| 上次手工重排 | 384/1000（38.4%） | 70/288（24.31%） | 3.716 | 129.9 | 136.5 |
| Bonsai 2.5 轨迹训练后的打分器 | 400/1000（40.0%） | 71/287（24.74%） | 3.675 | 128.8 | 135.2 |

相同起点比较使用每条贪心输出轨迹上所有能提出至少五个草稿的位置，每题 250 个。所有策略从同一批真实候选、相同的已提交文本开始。一个位置选错，本轮连续命中即结束。实际验证轮另用服务观测，各策略接受的前缀长度不同，访问的起点和总轮数也不同。两种五位指标的分母都限于实际可提出至少五个草稿的位置。在线比率取一次完整记录，三个独立无记录计时进程另行核对了每题草稿数、接受数和轮数。

四题的 1,000 个起点中，训练和手工都五位全中的有 362 个，仅训练命中 38 个，仅手工命中 22 个。647 个起点的 DFlash 候选集在五个位置均包含正确 token。其余位置要五位全中，还需要改变候选集合。相邻起点共享同一段输出，这 1,000 个起点只来自四道题。

| 中文小词典 | 19.6% | 19.6% | 19.2% | 95.8 → 94.3 |

| Python 滚动中位数 | 52.8% | 76.8% | 86.4% | 223.6 → 230.1 |

## 常规服务测速

| 策略 | 标准五题 token/s | 留出四题 token/s | 九题 decode token/s | 九题含 prefill 的 HTTP token/s | 草稿接受率 | 九题 ms/轮 | 三次独立进程的九题 decode token/s |
|---|---:|---:|---:|---:|---:|---:|---|
| 原生 DFlash7 | 136.3 | 121.6 | 129.4 | 117.6 | 35.64% | 27.02 | 128.8 / 129.5 / 129.8 |
| 上次手工重排 | 142.2 | 129.9 | 136.5 | 123.3 | 38.77% | 27.23 | 136.3 / 135.4 / 137.8 |
| Bonsai 2.5 轨迹训练后的打分器 | 140.8 | 128.8 | 135.2 | 122.4 | 38.17% | 27.17 | 132.7 / 136.4 / 136.7 |

单卡 MI210 运行 llama.cpp，目标模型为 Ternary-Bonsai-2.5-27B-Q2_0-mtp，草稿为 Bonsai 2 微调的 DFlash2 Q4_K_M。所有策略均使用前次验证过的 Q2_0 八列内核，七个草稿，单槽贪心、seed 1、8192 上下文、F16 KV、FA 开启，关闭提示缓存。每题固定 256 个输出 token。每个服务进程以 32 个 token 热身，三轮交错运行三种策略，轮换题目顺序。decode 速度用总输出 token 数除以总生成时间，HTTP 速度计入 prefill。前次实验已核对无推测贪心输出，本次 108 个在线审计及计时请求逐条复核了相同的 token ID 和文本。

训练后的轮时为 27.17 ms，达到 200 token/s 需要平均每轮交付 5.43 个 token，本次为 3.67。速度和每轮产出均以真实在线请求为准。

## 训练与数据划分

- 新写了 96 条中英文提示，覆盖说明、改写、代码、算术、结构化输出和叙事。前 80 条用于更新参数，另 16 条用于选择训练轮次和残差系数。九条最终评测提示全部留在这两组之外。原手工重排曾在标准五题选过参数，四条留出题用于检验迁移效果。每条由 Bonsai 2.5 贪心生成 144 个 token，训练与验证分别有 11,520 和 2,304 个目标 token。采集时运行草稿但清空其提议，由目标模型逐 token 决定序列。
- 训练集共 11,360 个验证起点。沿正确前缀对 16 个候选取样，得到 53,257 个可监督的位置。另有 6,509 个位置的正确 token 缺席，该起点的监督前缀在那里结束。推理只访问草稿分数、候选 ID、此前已经选定的草稿 token 和已经生成的文本。
- 在手工分数上拟合一个残差打分头。每个候选使用 32 项特征，涵盖基础候选次序、条件分数、不同前驱下的分数变化、下一位候选的分数差，以及已生成文本中的重复情况。单隐层有 24 个 ReLU 单元，另为 1,927 个训练中多次出现的 token 学习偏置。用列表交叉熵拟合目标模型选中的候选，前五位样本权重为后两位的 1.5 倍。
- 使用独立验证集上的共同起点五位全中率选择检查点，同分时看模拟每轮产出。选中第 2 轮，残差系数 1.0。验证集手工与训练分别为 601/2208 和 619/2208。打分器冻结后才读取原九题的候选轨迹，C++ 导出版本在验证集复现了选中检查点的命中计数。

## 使用实验权重

trained.bin 是冻结的候选打分权重，trained.so 可由下列命令编译为用于测速的 Linux 实验模块。依赖本项目 llama.cpp 的 C++ ABI，供单槽、温度 0 的 DFlash7 使用。实验只在独立服务进程运行。启动该实验服务时将 DFLASH_SCORER 设为 trained.bin 的绝对路径，并将本目录源码编译出的 trained.so 放在 LD_PRELOAD 的最前面。本分支的 libllama 已含 DFlash 权重变换修正。保持原服务的其他设置。

```sh
export DFLASH_SCORER="$SCORER_DIR/trained.bin"
export LD_PRELOAD="$SCORER_DIR/trained.so${LD_PRELOAD:+:$LD_PRELOAD}"
```

从随附源码重新构建打分模块与训练样本提取程序时，可在本目录使用以下命令。

```sh
g++ -O3 -march=native -std=c++17 -shared -fPIC -I"$LLAMA_CPP/include" -I"$LLAMA_CPP/common" -I"$LLAMA_CPP/ggml/include" trained-rank.cpp -ldl -o trained.so
g++ -O3 -march=native -std=c++17 extract.cpp -o extract
```

训练数据划分见 [training-prompts.json](training-prompts.json)。每批启动独立服务，先运行 32 token 的热身请求，再按顺序运行 16 个提示。在单槽服务中预加载 capture.cpp 编译的动态库，设 `PREFIX_MODE=dense` 和 `PREFIX_DUMP` 输出该批候选。以 `teacher0-1` 至 `teacher5-1` 命名各批的候选二进制与包含 warmup、requests、token ID 的响应 JSON，再运行 make-data.py 和 train.py 即可复现训练。
